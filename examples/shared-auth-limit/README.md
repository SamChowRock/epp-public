# 两个 API 的登录额度观察页

第 40 章已有浏览器边界与单进程登录额度。本页让浏览器交替访问两个真实 API，观察第 41 章共享额度的结果。它只负责转发和显示，不实现认证或额度决定。无需安装新依赖，使用项目固定的 Node.js 24.22.1。

## 准备和启动

在配套仓库根目录操作。先按本章主 README 准备独立练习数据库、执行迁移，并启动两个**正式 API 进程**：端口分别为 3341、3342，连接同一个练习库，两者的 `APP_ORIGIN` 都设为 `http://127.0.0.1:8341`。保留既有数据库连接和签名配置；不要把凭据写进本目录或浏览器页面。第 40 章的旧代码反例须另用旧快照启动，观察页没有“切回 Map”的开关。

本页固定使用虚构用户 `e4141e41-5a7c-49b1-b741-41e4141e4141` 和明显虚构的错误密码。练习前确认练习库中不存在该用户，不要为它建立真实账号。请求符合 `LoginSchema` 的格式；`401` 来自正式认证流程。

第三个终端执行：

```bash
node examples/shared-auth-limit/server.mjs
```

用浏览器打开 `http://127.0.0.1:8341/`。页面地址必须使用 `127.0.0.1`，不要改成 `localhost`。启动日志显示页面及 A/B 上游地址。

可在启动前显式改端口（每个上游仅允许 `http://127.0.0.1:端口`，不带路径、查询或认证信息）：

```bash
PORT=8341 \
AUTH_LIMIT_API_A=http://127.0.0.1:3341 \
AUTH_LIMIT_API_B=http://127.0.0.1:3342 \
node examples/shared-auth-limit/server.mjs
```

若改页面端口，两个 API 的 `APP_ORIGIN` 也要改为新的页面源。观察页只监听本机回环，`NODE_ENV=production` 时拒绝启动。

## 观察

- “A / B · 发送一次”各发送一次；“A + B · 并发两次”同时启动两个请求，不等 A 完成再发送 B。
- 每次固定 `POST /auth/login`，携带页面的原始 Origin、固定 `X-Epp-Request: 1` 和合成凭据。浏览器调用 `/api/a`、`/api/b` 时不提交任何真实密码或会话。
- 请求记录按**发送顺序**占位并更新，显示 API、上游端口、真实 HTTP 状态、业务码、`Retry-After` 和请求 ID。并发比较栏明确显示 A/B 各自状态，不把返回顺序当作发送顺序。
- 先消耗九格，再并发两次，正常情况下会看到一个凭据拒绝、一个 `429/AUTH_RATE_LIMIT`。窗口从第一份获准请求开始，等待真实窗口结束再试；不要在过程中重置数据库。
- “清屏”只清本页记录，不重置计数，不回收请求，不重置发送序号。刷新页面会丢失显示记录。页面不使用本地存储。
- 不自动重试。断连可能发生在数据库已扣额度以后；“未取得 API 响应”不能证明没有消耗额度。观察代理生成的 `502` 使用 `OBSERVATION_*` 业务码，JSON 中 `status: null`，区别于已经取得的正式 API 响应。

观察页不转发调用者的 Cookie、Body、`Forwarded` 或 `X-Forwarded-*`，不接收任意目标或任意 API 路径。正式 API 看到的来源是观察代理的回环连接，两端应保持本章默认的不信任转发头配置。这能观察同一来源跨进程共用额度，不能模拟不同用户、设备或公网 IP。正确登录和已登录会话读取使用既有 Postman 路线，本页不保存会话或返回 `Set-Cookie`。

## 验证与停止

```bash
node --test test/shared-auth-limit-example.test.mjs
```

此专项测试使用临时回环 HTTP 上游核对固定路由、Origin、结果字段、并行发送和失败不重试，并执行页面脚本核对显示顺序及清屏行为；它不是正式认证或数据库验收。真实 API、共享数据库和浏览器实拍按本章正文另做。

完成后在观察页终端按 Ctrl+C，并按正文停止本轮两个 API。停止页面或清屏都不会删除练习数据。

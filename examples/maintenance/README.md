# 第 81 章　运行一批头像清理，再按 ID 交接

在[第 74 章入口实验](../tls-trust/README.md)结束后恢复私有回环入口，沿用[跨环境部署交接记录](../portable-release/README.md)和[第 72 章的服务身份](../service-roles/README.md)。在本轮恢复的独立副本中保留原账号、收据及配对桶。运行角色、计时器和逐项日志是本次新增内容，原有[头像清理命令](../../database/chapter-51/clean.mjs)及可选的单笔 ID 继续使用。以下文件的部署目标是 Debian 13 的系统级 systemd。

1. 使用与非空库成对恢复的私有桶，在这份副本上启动 API，用[已有集合](../../requests/chapter-51.postman_collection.json)的 05、20、15 登录并取得写令牌。用 25 连续发布两张图，分别记录旧版与当前 avatarId。连接本轮库的 psql 中输入 `\set attempt_id '本轮UUID'`，从配套根执行 `\i examples/maintenance/preview.sql`。当前版应为 live、当前引用为真；被替换的旧版过 30 秒才可领取。[单笔预演](preview.sql)是只读查询。
2. 以实例管理员建立普通登录角色 `epp_cleanup`，用 `\password epp_cleanup` 设置独立口令，不加入现有服务角色。在隔离目标库用有权授权的所有者设置 `\set expected_db epp_ch73_handoff`（换成建库时记下的名字），执行 `\i examples/maintenance/grants.sql`。[授权文件](grants.sql)只追加列出的权限。配置专用对象凭据：第 60 章本地存储可在原私有配置内新增独立身份，作用域 `Write:avatars`，保留原身份；支持细粒度策略的服务授予头像键的删除权限。观察端使用独立的读身份。
3. 从配套根 `nvm use`、`npm ci`、`npm run ci:check`。按第 73 章交付 `dist`、清单、锁、.npmrc 和目标平台的生产依赖到 root 管理的 `/opt/epp73/release`，再按原路径带上 `database/chapter-51/clean.mjs`、`scripts/verify-database.mjs`。沿用 `/opt/epp72/node/bin/node` 或修改为实际绝对路径。在 Linux 建立系统用户和同名组 epp-cleanup；把含 DATABASE_URL 及 AVATAR_S3_ENDPOINT、AVATAR_S3_BUCKET、AVATAR_S3_ACCESS_KEY、AVATAR_S3_SECRET_KEY 的专用配置装成 `/etc/epp73/cleanup.env`，root:epp-cleanup、0640。核对实际连接角色、库、端点、桶和当前头像。
4. 在 release 用 `sudo -u epp-cleanup env -i /opt/epp72/node/bin/node --env-file=/etc/epp73/cleanup.env database/chapter-51/clean.mjs epp_ch73_handoff http://127.0.0.1:18633 avatars 本轮到期UUID`。末项只筛选该笔。见到 deleted-or-absent 后，用[对象 HEAD 命令](../../database/chapter-51/head-avatar.mjs)及观察端配置分别检查旧版和当前版。实际库、端点和桶三个参数应独立从交接记录抄取。
5. 核对[一次性服务](epp-avatar-clean.service)中的路径、用户、预期目标，和[每分钟计时器](epp-avatar-clean.timer)一起装入 /etc/systemd/system。运行 `sudo systemd-analyze verify /etc/systemd/system/epp-avatar-clean.{timer,service}`、`sudo systemctl daemon-reload`。手动 `sudo systemctl start epp-avatar-clean.service` 看逐项结果，再 `sudo systemctl start epp-avatar-clean.timer`。`systemctl list-timers --all epp-avatar-clean.timer` 显示计划与上次触发，`sudo journalctl -u epp-avatar-clean.service --since '10 minutes ago' -o short-iso` 显示实际执行。一批最多 20 项，`TimeoutStartSec=120s` 给整次执行设上限。
6. 等有过一次计划触发后停 timer，等 service 结束。再产生一笔旧版，跨过原来的 NEXT；用[到期量与最老时刻](backlog.sql)留基线。重新 start timer，按 ID 查补跑及下一轮。做并发对照时再次停 timer，让一个带指定 ID 的前台进程在 dist/src/avatar-cleanup.js 的 `await objects.remove(id)` 暂停。第二个进程分别检查这笔、另一笔到期项与当前项；自然等满第一笔的五分钟，再处理它并恢复前一个进程。
7. 在新的旧版到期后单独断开清理端到本轮对象端点的连接，手动 start service。用失败 ID 对照 journal 的错误、退出状态与库内下次时刻。恢复原端点后在期限前、期限后各观察一次，最终用同一 ID 核对 deleted-or-absent、旧键不可见及当前键可读。做完停 timer 并等 service 退出。若已启用开机启动，使用 `sudo systemctl disable --now epp-avatar-clean.timer`。
